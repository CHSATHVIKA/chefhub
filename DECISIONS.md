# Decisions and assumptions

- **Java version:** the code targets Java 17 (`java.version=17`). It was built locally on JDK 25, and Lombok is pinned to 1.18.42, which supports JDK 25.
- **Maven:** I used the Maven wrapper (`mvnw`) so nobody needs Maven installed. The Docker image builds with the official Maven image.
- **Local DB password:** it lives in `backend/local.properties` (gitignored), which Spring loads via `spring.config.import`. The committed default is `root`, so no real password is in git.
- **DTOs:** they're Java records with a static `from(entity)` mapper. Records are short and immutable. The mapping is plain field copying, so it doesn't break the "logic only in services" rule.
- **Cuisines:** these are stored as one comma-separated string on ChefProfile instead of a separate table. Search uses `LIKE`. That's simple enough for this scale.
- **Price:** the booking total is the chef's flat price per visit. Menu prices are shown for information only.
- **Tier:** chefs pick Standard or Premium themselves in their profile. Admin approval is what controls visibility.
- **Block chef:** blocking sets `approved=false`, which hides the chef from search and stops new bookings. Existing bookings stay as they are, and the chef can still log in.
- **New chefs:** they get an empty profile with `approved=false` and must fill it in. The admin then approves them.
- **Admin accounts:** these can't be created through register. The only admin is seeded.
- **Double booking:** the slot row is loaded with `PESSIMISTIC_WRITE` inside the booking transaction. The service checks both the `booked` flag and whether an active booking exists. Cancelling or rejecting a booking frees the slot.
- **Status transitions:** chef can do PENDING->CONFIRMED/REJECTED and CONFIRMED->COMPLETED. Customer can do PENDING/CONFIRMED->CANCELLED. Everything else returns 400.
- **Slots:** a chef can't add overlapping slots on the same day, and can't delete a slot that is booked.
- **Search:** only approved chefs are shown. Page size is capped at 50.
- **Seed data:** the seed runs only when the users table is empty. Slots are generated relative to today, so they're always in the future.
- **Schema:** I used `ddl-auto=update` instead of Flyway to keep setup simple. Flyway is listed in the README as a future improvement.
- **Docker compose:** MySQL is exposed on 3307 so it doesn't clash with a local MySQL on 3306.
- **Images:** they're Unsplash URLs, and the frontend falls back to a default image if one fails to load.
- **Tailwind:** I used v3 (config file + PostCSS) because it's more widely documented than v4.
- **GitHub push and Vercel deploy:** I couldn't do these from this session. The `gh` and `vercel` CLIs weren't installed and both need an interactive login. The exact commands are in NEXT_STEPS.md.
